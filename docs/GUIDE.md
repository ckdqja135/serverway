# Serverway 안내

트래픽 하나가 오가는 작은 서버에서 시작해, 감당할 수 있을 때까지 끝없이 키우는 마라톤 게임입니다.
화면의 요청과 서버는 모두 게임 안의 가상 객체이며 실제 네트워크에는 아무것도 보내지 않습니다.

## 실행

    scripts/run.sh

http://127.0.0.1:7800 을 엽니다. Go와 Node가 필요합니다.
화면만 고칠 때는 `cd web && npm run dev` 후 http://127.0.0.1:7880

## 배포

게임 규칙(Go)은 두 곳에서 돌 수 있고, 빌드할 때 정합니다.

| 빌드 | 규칙이 도는 곳 | 쓰는 때 |
|-|-|-|
| `npm run build` | 브라우저 안 (WebAssembly) | Vercel 같은 정적 배포. 서버가 필요 없고 이어 하기는 브라우저에 저장 |
| `VITE_SERVER=1 npm run build` | Go 서버 | `scripts/run.sh`. 판정을 서버가 함 |

Vercel에는 `web` 폴더를 올립니다. 규칙 코드나 `balance.json`을 바꾸면 `scripts/wasm.sh`를 실행해 `web/src/wasm`을 다시 만들어야 하고, 잊으면 `go test ./...`가 실패합니다.

## 튜토리얼

처음 새 게임을 누르면 연습용 판에서 튜토리얼부터 진행합니다. 한 번이라도 끝내거나 건너뛰면 그 뒤로는 바로 본 게임이 시작됩니다.
시작 화면의 튜토리얼 버튼으로 다시 할 수 있고, 무엇을 언제 늘리는지는 설정의 게임 규칙에도 있습니다.
연습용 설정은 `server/internal/sim/practice.go`, 단계와 글은 `web/src/ui/Lesson.tsx`에 있습니다.

## 규칙

- 요청은 클라이언트, 서버, DB 순서로 처리된 뒤 지나온 링크로 되돌아와야 완료됩니다.
- 경로는 지금 보낼 수 있는 링크 중 `이동 시간 + 도착지 예상 대기`가 가장 짧은 곳입니다. 같으면 먼저 만든 링크입니다.
- 서버나 DB의 대기열이 꽉 차면 요청은 링크 위에서 기다리고, 밀린 줄이 뒤로 번집니다. 줄의 맨 앞이 병목입니다.
- 링크는 왕복 2차선이고 차선마다 초당 전송 수가 정해져 있습니다. 서버와 DB의 처리 용량과는 별개입니다.
- 실패: 502 경로 없음, 503 클라이언트 대기열 초과, 504 처리 기한 초과, 500 장애
- 철거하면 새 요청만 막고, 이미 나간 요청이 돌아온 뒤 사라집니다. 비용의 절반을 돌려받습니다.
- 마라톤: 끝나는 시간이 없습니다. 클라이언트, 트래픽, 보드, 장애가 계속 늘어나고 서비스 상태가 0이 되면 끝납니다. 설정에서 직접 마칠 수도 있습니다.
- 8분부터는 전체 트래픽이 점점 더 빠르게 늘어납니다.
- 구간(45초에서 시작해 75초까지 길어짐)마다 예산을 받고 개선 작업을 하나 고릅니다. 구간 수입은 계속 늘어나고, 가진 예산의 15%를 그 구간 수입까지 더 줍니다. 보상 카드는 고르기 전과 후의 실제 값을 보여 줍니다. 선택지는 구간마다 2, 3, 4, 5개로 늘고 그 뒤로는 계속 5개이며, 4개부터는 2개를 고릅니다.
- 요청을 `5 + 서버, DB, Redis 대수`건 완료할 때마다 예산을 1 법니다. 늘어난 만큼 운영비가 들지만, 구간마다 처리 수익이 10%씩 오릅니다.
- 성장 단계에 오르면 새 기능이 열립니다.
  - 성장 서비스(900건): 저장 공간. DB가 처리할 때마다 차고, 가득 차면 속도가 40%로 떨어집니다. DB를 눌러 늘리거나 샤드를 추가하면 공간에 비례해 다시 나뉩니다.
  - 국민 서비스(3,000건): Redis와 WebSocket. Redis는 서버와 이으면 요청의 일부를 DB 대신 응답합니다. WebSocket은 클라이언트와 서버 사이 링크를 전환해 2배 빠르고 2배 많이 보내며 처리 수익이 1.5배입니다.
- 서버, DB, Redis, 링크 레벨에는 사실상 끝이 없습니다(40레벨). 서버, DB, Redis는 지을수록 조금씩 비싸지고 80대까지 지을 수 있습니다.
- DB 샤드: 어느 샤드로 가도 처리된다고 단순화했습니다. 서버에서 샤드로 링크를 이어야 쓰입니다.
- 장애는 14초에서 16초 전에 예고합니다. 대상은 많이 쓰는 서버나 링크입니다. 장애 중 실패는 페널티가 절반입니다.
- 새 클라이언트 자리는 무작위로 고르고, 못 찾으면 모든 칸을 살펴 반드시 나옵니다. 빈자리를 메워 막을 수 없습니다.
- 시드를 직접 넣거나 같은 시드로 다시 시작한 판은 연습 기록이라 최고 기록에 남지 않습니다.
- 처음 45초는 지지 않습니다. 연결이 끊기거나 창을 가리면 게임이 멈춥니다.

## 조작

| 입력 | 동작 |
|-|-|
| 드래그 | 클라이언트에서 서버로, 서버에서 DB로 연결 |
| 클릭 | 선택, 빈 곳은 선택 해제 |
| Space / S | 일시 정지 / 속도 |
| 1 / 2 / 3 / 4 | 연결 / 서버 추가 / DB 샤드 추가 / Redis 추가 |
| U / Delete | 업그레이드 / 철거 (확인 후) |
| Esc | 취소 |

## 밸런스 조절

`server/internal/sim/balance.json`에 예산, 비용, 요청 발생률, 처리 시간, 대기열, 기한, 페널티, 장애 시점, 보드 확장, 보상, 마라톤 성장 속도(`endless`)가 모두 있습니다.
다른 파일을 쓰려면 `SERVERWAY_BALANCE=파일경로`로 실행합니다.

    cd server
    go test ./...                        # 규칙 테스트
    go run ./cmd/playtest                # 봇 전략별 결과
    go run ./cmd/playtest 기록.json      # /api/sessions/{id}/replay 로 받은 판을 다시 계산

## 구조

| 위치 | 역할 |
|-|-|
| server/internal/sim | 네트워크 없이 동작하는 게임 규칙 |
| server/internal/game | 세션, WebSocket, 변경분 전송 |
| server/cmd/wasm, web/src/worker.ts | 브라우저 안에서 규칙 실행 |
| web/src/wire.ts | 규칙이 도는 곳과 주고받는 길 (워커 또는 WebSocket) |
| web/src/client.ts | 게임 상태 보관과 화면 시계 |
| web/src/board.ts | Canvas 보드 |
| web/src/ui | React HUD와 패널 |
| web/src/guard.ts | 우클릭과 개발자 도구 단축키 막기 (빌드한 화면에서만) |
