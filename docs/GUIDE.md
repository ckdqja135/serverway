# Serverway 안내

트래픽 하나가 오가는 작은 서버에서 시작해, 감당할 수 있을 때까지 끝없이 키우는 마라톤 게임입니다.
화면의 요청과 서버는 모두 게임 안의 가상 객체이며 실제 네트워크에는 아무것도 보내지 않습니다.

## 실행

    scripts/run.sh

http://127.0.0.1:7800 을 엽니다. Go와 Node가 필요합니다.
화면만 고칠 때는 서버를 켠 채 `cd web && npm run dev` 후 http://127.0.0.1:7880

## 규칙

- 요청은 발생지, API, DB 순서로 처리된 뒤 지나온 링크로 되돌아와야 완료됩니다.
- 경로는 지금 보낼 수 있는 링크 중 `이동 시간 + 도착지 예상 대기`가 가장 짧은 곳입니다. 같으면 먼저 만든 링크입니다.
- 서버 대기열이 꽉 차면 요청은 링크 위에서 기다리고, 밀린 줄이 뒤로 번집니다. 줄의 맨 앞이 병목입니다.
- 링크는 왕복 2차선이고 차선마다 초당 전송 수가 정해져 있습니다. 서버 처리 용량과는 별개입니다.
- 실패: 502 경로 없음, 503 발생지 대기열 초과, 504 처리 기한 초과, 500 장애
- 철거하면 새 요청만 막고, 이미 나간 요청이 돌아온 뒤 사라집니다. 비용의 절반을 돌려받습니다.
- 마라톤: 끝나는 시간이 없습니다. 발생지, 트래픽, 보드, 장애가 계속 늘어나고 서비스 상태가 0이 되면 끝납니다. 설정에서 직접 마칠 수도 있습니다.
- 8분부터는 전체 트래픽이 점점 더 빠르게 늘어납니다.
- 구간(45초에서 시작해 75초까지 길어짐)마다 예산을 받고 개선 작업을 하나 고릅니다.
- 요청을 `5 + 서버 대수`건 완료할 때마다 예산을 1 법니다. 서버가 늘면 운영비만큼 더 많이 완료해야 합니다.
- API, DB, 링크 레벨에는 사실상 끝이 없습니다(40레벨). 서버는 지을수록 조금씩 비싸지고 80대까지 지을 수 있습니다.
- DB 샤드: 어느 샤드로 가도 처리된다고 단순화했습니다. API에서 샤드로 링크를 이어야 쓰입니다.
- 장애는 14초에서 16초 전에 예고합니다. 대상은 많이 쓰는 API나 링크입니다. 장애 중 실패는 페널티가 절반입니다.
- 처음 45초는 지지 않습니다. 연결이 끊기거나 창을 가리면 게임이 멈춥니다.

## 조작

| 입력 | 동작 |
|-|-|
| 드래그 | 발생지에서 API로, API에서 DB로 연결 |
| 클릭 | 선택, 빈 곳은 선택 해제 |
| Space / S | 일시 정지 / 속도 |
| 1 / 2 / 3 | 연결 / API 추가 / DB 샤드 추가 |
| U / Delete | 업그레이드 / 철거 (확인 후) |
| Esc | 취소 |

## 밸런스 조절

`server/internal/sim/balance.json`에 예산, 비용, 요청 발생률, 처리 시간, 대기열, 기한, 페널티, 장애 시점, 보드 확장, 보상, 마라톤 성장 속도(`endless`)가 모두 있습니다.
다른 파일을 쓰려면 `SERVERWAY_BALANCE=파일경로`로 실행합니다.

    cd server
    go test ./...                        # 규칙 테스트
    go run ./cmd/playtest                # 봇 전략별 결과
    go run ./cmd/playtest 기록.json      # /api/sessions/{id}/replay 로 받은 판을 다시 계산

## 구조

| 위치 | 역할 |
|-|-|
| server/internal/sim | 네트워크 없이 동작하는 게임 규칙 |
| server/internal/game | 세션, WebSocket, 변경분 전송 |
| web/src/client.ts | 서버 상태 보관과 화면 시계 |
| web/src/board.ts | Canvas 보드 |
| web/src/ui | React HUD와 패널 |
